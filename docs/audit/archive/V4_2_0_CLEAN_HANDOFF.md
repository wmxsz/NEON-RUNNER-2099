# v4.2.0-G 综合升级审计：原生渲染预算与赛博跑道抗闪烁

> 当前开发基线：v4.2.0-G（Android versionCode=38）。本版是一次集中式渲染链路优化，不是以版本号或重复检查计数。

## 问题范围与修改决策

检查重点集中在原生渲染预算与赛博跑道高频线条两条互相关联的链路：设备档位此前需要把辉光与阴影配置落实到实际引擎属性；跑道上的高频细线在远景缩成亚像素时容易断续/闪烁。保留模型与贴图本身，避免为凑改动数量盲目增加面数或生成冗余资源。

## 实质改动

1. **原生方向光阴影分档**：高档启用 `DirectionalLight3D.SHADOW_PARALLEL_4_SPLITS`，最大距离 60m、渐隐起点 0.82、开启 split blending；中档启用双分区、42m、渐隐起点 0.72；低档关闭方向光阴影，不靠降低原生分辨率或关闭 MSAA 省成本。
2. **真实 Environment 辉光层预算**：高档配置 5 个有效层，中档 3 个，低档常态关闭并清零所有层；低档超频只临时恢复前两层，结束后再次清零。档位不仅改变亮度，而是改变实际参与合成的层级。
3. **跑道细线的屏幕空间抗闪烁**：机械接缝、蚀刻电路、车道导轨、中心导轨、同步条及数据刻度使用 `fwidth()` 屏幕空间覆盖率，并在细于像素时降低覆盖率。没有增加纹理采样，也没有降低 3D 渲染比例；原有 4× MSAA 与 16× 各向异性过滤保留。
4. **遥测可观察性**：`Telemetry.report.renderBudget` 记录实际生效的档位、阴影状态/模式/距离、有效辉光层与超频状态。这样后续设备分析可以对照真实渲染配置，而非只读一个预设名。
5. **运行时机制合同**：新增高/中/低档位渲染预算测试，断言阴影模式、最大距离、有效辉光层数，以及低档超频时的两层临时恢复和结束回退。
6. **初始化一致性**：在 World 创建原生 Environment 与方向光后，立即应用完整默认渲染预算；随后设备检测可替换成对应档位，避免首帧的环境配置与最终档位不一致。

## 引擎兼容性依据

本方案按 Godot 4.7 文档使用原生 API：

- [DirectionalLight3D](https://docs.godotengine.org/en/4.7/classes/class_directionallight3d.html)：四分区阴影更精细但成本更高，双分区是中间选项，缩小阴影距离可控制成本。
- [Environment](https://docs.godotengine.org/en/4.7/classes/class_environment.html)：辉光各层的启用与强度控制实际效果及成本。
- [Godot Shader Language](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/shading_language.html)：使用 `fwidth()` 估算屏幕空间变化，作为程序化细线的抗锯齿依据。
