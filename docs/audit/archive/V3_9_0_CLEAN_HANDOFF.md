# v3.9.0-G — 平滑相机冲击反馈与可调震动审计

> 当前基线：v3.9.0-G / Android versionCode 35。目标引擎：Godot 4.7.2-stable。

## 本轮实质问题

旧版 `_update_camera()` 每个渲染帧独立抽取随机偏移，再把已经偏移的 `cam.position` 作为下一帧 `dampf()` 的输入。随机位移由此污染相机跟随基线，观感上更像高频碎抖，而不是有方向、有衰减的冲击反馈。原始 `game.cam_shake` 以 `raw_dt * 8.0` 衰减，0.25–0.30 的初始值理论上约 31–38ms 即归零；在卡顿/恢复的大帧间隔中也可能瞬间消失。

## 实际修改

1. **独立相机基线：**`_camera_base_position` 只由目标跟随、死亡偏移与落地 dip 更新；最终 `cam.position` 在最后一步叠加震动向量，避免偏移回灌到阻尼。
2. **连续冲击波：**删除逐渲染帧 `U.randf_range()`，改为多频正弦波与 `U.dampf()` 包络，目标冲击值衰减速率改为 1.9/s。三组频率在 10 秒内分别完成 44/32/61 个周期，相位按这个共同周期取模，避免长期运行相位无界增长并保持边界连续。
3. **大帧间隔保护：**相机积分 `camera_dt` 限制在 `[0, 0.05]` 秒；落地 dip 夹到零，不会因单次慢帧降至负时长。它只限制相机呈现积分，不改变 60Hz 游戏模拟或回放输入序列。
4. **玩家可调：**新增 `cameraShake` 默认 `0.75`；设置页原生 HSlider 支持 0–100% 实时预览。提交时复用现有持久化流程，失败会回滚运行值。旧档通过默认配置补齐，非数字/NaN/Inf 会回退，有限值被夹制到 `[0,1]`。
5. **回归护栏：**`test_headless.gd` 增加默认值断言；`validate_release_contracts.py` 检查稳定基线、震动 envelope、随机抖动移除、有限数字验证、范围夹制、滑块和设置回调。

## 已执行的离线验收与边界

- **工作目录与最终 ZIP 解压目录均通过** `sh tools/run_offline_checks.sh`；重新打包后再次干净解压，使用同一套门禁复验。ZIP `zip -T` 完整性检查通过。
- 项目/版本/资源身份通过；9 个 GLB 模型、6 张 PBR 贴图、12 个 SVG、78 个字面资源引用、104 个唯一导入 UID 均通过相应检查。21 个 GDScript 通过词法结构扫描，但这不等于 GDScript 语义编译。
- **相机公式参考模型**按 60/90/120 Hz 对同一冲击输入进行数值模拟，跨刷新率共同采样位置差低于 `0.005` 个相机单位；强度 `0` 时偏移为零；10 秒周期取模连续。该检查复现方程，不执行 Godot 渲染器。
- Godot 4.7.2-stable 执行文件未找到，官方分发域名在该环境也无法解析。因此 GDScript 语义编译、着色器真实导入、60/90/120Hz 录屏、Android FPS/p95/GPU/温度与 APK 导出**均未运行**。源码与数值门禁通过不等于游戏运行无 Bug 或帧率认证。
