# v3.0.0-G — 全量工程基线刷新审计

> 当前开发基线：v3.0.0-G（Android versionCode=25）。本报告描述当前交付，不替代历史版本审计。

## 本批目标

收敛版本身份、资源库存、开发入口、静态检查和关键性能更新策略，避免每次发版都复制一套硬编码版本检查器，并避免旧的审计摘要在项目根目录被误认为当前状态。

## 已完成的源码与工程更新

1. **建立唯一发布元数据：**根目录 `RELEASE_MANIFEST.json` 记录版本、Android build number、项目名、主场景、渲染器、视口、包名、ABI、备份策略、Godot 系列、物理频率、回放 schema/ruleset 与模型/纹理/音乐/SFX 资源数量。项目配置和导出预设通过检查器与该元数据对齐。
2. **发布检查器通用化：**上一版绑定特定版本号的检查器重整为通用发布检查器，去掉随着版本更新不断扩散的旧版本文件名；新增 `tools/validate_project_integrity.py` 检查 manifest、配置、固定 `res://` 引用、UID sidecar、资源清单与历史文件位置。
3. **当前/历史完全分层：**所有旧版本审计和阶段检查移入 `docs/audit/archive/`；旧版本更新明细另存于 `docs/CHANGELOG_HISTORY.md`。当前 README、当前更新日志、发布状态与验收清单只描述 v3.0.0-G。当前脚本注释中的历史版本标签、旧来源系统与阶段编号也被改写成职责说明。
4. **平台身份与导出目标统一：**项目名、主场景、Mobile 渲染器、412×915 竖屏视口、Android 包名、arm64-v8a ABI、数据备份开关和 APK 文件名均纳入清单校验；发布 keystore 仍保持空白，确保私密凭据不被打入源码。
5. **有限帧率目标：**设备档位使用配置化 60/90/120 FPS；尝试读取显示刷新率并限制目标帧率，刷新率未知时回退 60 FPS，不再以 `Engine.max_fps = 0` 代表高档无限制渲染。实际设备支持情况待运行时验证。
6. **章节主题更新节奏：**章节边界切换与显式重置仍即时应用；渐变期间对 Environment、道路、门框和导入模型材质的参数更新按配置限制到最多 30 Hz，减少 60 Hz 物理循环中重复写入大量视觉属性。材质渐变平滑度及所有主题变体需引擎画面验收。
7. **统一离线入口：**`sh tools/run_offline_checks.sh` 先执行 Python 工具语法，再运行项目元数据、视觉资源、障碍模式库、源码契约及 Markdown 本地链接检查。若找到 Godot，会核对 4.7.x 系列后尝试 headless 导入和主场景 smoke test。
8. **旧注释清理：**把活动 GDScript 的历史版本标签与旧实现来源注释改写为当前系统职责，避免代码注释将旧迭代方案误示为当前架构。新增完整性护栏，防止这些标签再次混入活动脚本。
9. **交付边界明确化：**`docs/RELEASE_STATUS.md` 区分离线静态检查与引擎/设备验收；`RELEASE_MANIFEST.json` 明确当前没有 APK、没有发布签名、没有本环境内的引擎语义验证和 Android 设备验证。

## 离线检查覆盖

- GLB 模型与 PBR 贴图库存、尺寸、基本几何预算与资源引用。
- 9 首 OGG 与 12 个 WAV 的资源数量、音频调用契约与独立全轨解码。
- 固定 `res://` 路径、导入 UID sidecar 与唯一 UID 检查。
- 障碍模式库结构、DDA、随机数、回放、新局生命周期、存档事务、音频总线、输入队列及性能策略等源码契约。
- 当前版本号、Android `versionName`/`versionCode`、Godot feature、物理 tick、资源清单、当前文档基线和本地 Markdown 链接。
- ZIP 完整性与干净解压后再次运行同一套检查。

## 最终离线验收记录

以最终源码目录和打包后干净解压目录分别执行 `sh tools/run_offline_checks.sh`，两次均通过以下检查：

- 9 个 GLB 模型、6 张 1024×1024 PBR 贴图、55 处固定 `res://` 路径引用。
- 30 个项目导入 UID 唯一；完整性工具另外确认 19 个脚本/Shader UID sidecar 无重复/孤儿。
- 9 首 OGG 背景音乐和 12 个 WAV 短音效，共 21 个音频文件；最终 ZIP 解压后使用 FFmpeg 对每个文件进行完整解码，全部通过。
- 26 个障碍模式、47 个障碍定义、24 条芯片线；结构扫描未发现同一深度全封三条路线的硬障碍组合。该结果不替代连续时间物理可解性模拟。
- 29 份 Markdown 本地链接有效；16 个 GDScript 文件通过基础引号/括号词法检查和空白规范检查。
- 项目版本、Android 包名/版本名/版本码/ABI/备份设置、主场景、渲染器、视口、发布凭据空白规则与资源库存均与发布清单一致。
- 压缩包完整性测试通过，最终交付包干净解压后再次运行整套离线检查通过。

## 当前环境结果

离线检查可以执行并对静态资源、文件引用和特定源码约定进行验证。但当前工作环境没有 `godot`/`godot4`、Android `adb` 或已配置的 Android 导出工具，因此：

- GDScript 静态词法检查不能证明 GDScript 语义编译成功。
- 资源文件存在不能证明 Godot 已成功导入场景、Shader 或 GLB。
- 30 Hz 主题写入与 60/90/120 FPS 策略尚未在实际屏幕上验收。
- OGG/WAV 解码成功不代表设备上的混音响度和主观听感已通过。
- 未生成 APK，也未验证发布签名、安装、后台恢复、温度和长时间稳定性。

## 本版本后续验收门槛

1. 使用 Godot 4.7.x headless editor 完整导入项目并修复所有语义/资源导入错误。
2. 运行主场景，覆盖开局、连续重开、暂停/后台恢复、复活、BOSS、回放、任务领奖和存档失败路径。
3. 录制章节过渡与角色/材质画面，确认 30 Hz 更新不会出现可见卡顿、闪烁或突变。
4. 在不同刷新率设备上测量帧时间、1% low、GPU/CPU 时间、内存与温度，再决定是否调整各档预算。
5. 完成 Android APK 导出、安装、音频听感验收与正式签名检查。

## 结论

v3.0.0-G 是工程元数据、文档入口、静态检查器和部分性能更新节奏的一次统一基线刷新。报告不宣称项目已达到零缺陷，也不把离线静态检查描述为引擎编译或真机验收。当前版本的权威状态来源为 `RELEASE_MANIFEST.json` 与 `docs/RELEASE_STATUS.md`；历史细节请查看 `docs/CHANGELOG.md` 和归档报告。
