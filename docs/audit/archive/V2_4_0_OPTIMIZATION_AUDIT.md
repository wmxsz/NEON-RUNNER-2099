# v2.4.0-G 全局优化扫描与审计记录

## 本轮目标

在不破坏现有玩法 API、场景路径和美术资源的前提下，寻找容易在新局、触屏和低端移动 GPU 上触发的稳定性/性能问题，并修复能由源码直接证实的问题。

## 本轮完成的代码变更

### 1. 触屏手势的状态污染

**原风险：**输入层用共享的起点变量处理所有屏幕触控，没有区分 `InputEventScreenTouch.index`。多个触点可覆盖首个触点；如果一个手势开始时游戏正在运行、结束时游戏已进入暂停/菜单/新局，旧的抬手事件可能在状态恢复后被误认为跳跃。

**修复：**绑定活动触点 index；记录手势开始时是否允许游戏输入；忽略第二根手指；在输入启停/队列清空时清除活动手势；Main 不再直接写 `input.enabled`，通过 `set_enabled()` 统一切换。

**验证边界：**离线检查确认源码合同存在。多点触控与 Android 触屏事件顺序仍需实机验证。

### 2. 60Hz 碰撞结果对象复用

**原风险：**每一次 `Spawner.check()` 都创建一个新 `HitResult`。游戏运行期间这会按约 60 次/秒产生短命对象，尽管 Main 只同步读取本帧结果。

**修复：**改为缓存一个结果对象，并在检查开始时重置字段。重置时替换 `hit` 字典引用，不对其执行 `clear()`，避免意外清空由 Spawner 池拥有的障碍字典。

**契约：**返回对象是借用结果，只在下次 `check()` 前有效；当前 Main 立即处理结果，不保留引用。实际收益仍需在 Godot Profiler 中测量。

### 3. 无消费者的每帧分数信号

**原风险：**`Game.tick()` 每个物理步都广播 `score_updated`，但项目内没有任何连接者；Main/HUD 已通过当前 Game 状态更新显示。

**修复：**删除无消费者信号及其三处发送，避免冗余每帧广播，减少两个数据路径不一致的机会。

### 4. 按需遥测

**原风险：**设置关闭“显示 FPS”只隐藏 HUD 标签，Telemetry 仍持续累计帧数并每 0.5 秒读取 RenderingServer 指标、构造报告字典和发出信号。

**修复：**Telemetry 的采样启停与设置联动；关闭显示后跳过采样，重新开启时清零时间窗口和帧计数，避免混入过期样本。设备分级在启动时仍照常执行。

### 5. 移动端程序窗格 Shader

**原风险：**每个窗格像素会多次计算以 `sin(dot(...))` 为核心的哈希；楼群遮罩、窗格灯光、故障闪烁和招牌都依赖该函数，在移动 GPU 上属于值得优化的逐像素成本。

**修复：**替换为多项式哈希函数，减少三角函数调用，保留确定性随机分布。视觉图案会有变化，尚未用真实渲染比较 GPU 时间与画面质量。

### 6. 清理无效画质偏好

**原风险：**`quality=auto/high/mid/low` 被保存和校验，但设置 UI 不显示它、运行系统也没有应用它，属于不会产生效果的假设置。

**修复：**从默认 schema 和存档设置校验中移除该字段。旧存档包含此字段不会报错：当前加载过程只读取默认 schema 里承认的字段，因此旧值会被忽略。未新增会主动降低分辨率的选项。

## 其他发现：尚需实机/引擎决策

| 项目 | 为什么值得检查 | 当前处理 |
|---|---|---|
| 音乐章节首次切换 | 第一次 `load()` 可能引入资源读取尖峰；应先测量而不是直接预加载全部音乐造成启动内存/时间开销 | 记录为 Godot Profiler 检查项 |
| 后处理屏幕采样 | 色差需要多次采样全屏纹理，GPU 成本随屏幕分辨率增加 | 暂不降低画面；测量后再决定是否在普通速度跳过额外采样 |
| HUD 文本处理 | 已对分数/距离整数、芯片数、连击状态加入变化缓存；剩余开销待测 | 已避免无变化文本赋值，仍需用 Profiler 量化收益 |
| 场景静态物体与材质实例 | 城市 MultiMesh 已降低绘制调用，仍要检查不同 Android GPU 上的着色器/阴影/过绘成本 | 不盲目增删视觉细节，待真机采样 |
| 章节切换 / BOSS / 复活 | 状态联动复杂，静态契约无法完整验证 Tween、音频流和节点生命周期 | 按回归清单在引擎运行测试 |
| Android 发布签名 | 导出模板和 release keystore 未配置；无法由源码静态检查替代 | 等正式构建环境配置后再做发布包 |

- PBR 贴图尺寸和接缝指标。

- 玩法数值契约、随机种子、障碍时序、跨局生命周期与存档输入校验。
- 文档链接、GDScript 词法结构/空白格式、HUD 标签缓存、MultiMesh 状态边沿更新和部件基底预计算等新增代码合同。

## 未完成的最高优先级

**Godot 引擎级导入/编译和 Android 真机验证。** 本轮没有 Godot 可执行文件，因此没有声称通过 GDScript 语义编译、Shader 编译、实机触控、GPU 帧时间、热量或长时间稳定性测试。离线检查通过只能证明这些可由静态校验的约束通过。
### 7. MultiMesh 热路径：显隐状态边沿更新

**原风险：**对象池中所有未活动槽位每一帧都会将每个部件的 transform 再写一遍零缩放；部分障碍还在每帧给所有部件重新写入不变的实例色。

**修复：**池对象记录 `_render_active`，只在活动/隐藏状态发生变化时改缓存；隐藏槽只在活动→隐藏时写一次零变换，重新激活后照常每帧写活动 transform。障碍记录 `_render_style`，只有样式索引变化时才更新对应危险材质实例色。渲染结果和对象池容量不变，具体 RenderingServer/GPU收益须实测。

### 8. 预计算静态部件方向

**原风险：**每个活动 MultiMesh 部件每帧都会从固定 Euler 角重新构造 `Basis`，芯片和道具也有相同模式。

**修复：**在 `_part_mesh()` 初始化时计算 `base_basis`，运行时只叠加确实需要的旋转（旋翼、光束、芯片/道具自转），再应用缩放。

### 9. HUD 道具标签缓存与池映射保护

**原风险：**道具剩余秒数每次刷新都会清理并重新建立 Label 节点；此外渲染层出现了不再定义的 `pu_kinds` 名称，静态资源扫描不会发现这种运行期标识错误。

**修复：**按道具 kind 缓存 Label，只有显示秒数变化时才改文本，显隐状态也只在发生变化时更新；跨局重置只隐藏而不释放节点。渲染器按 `POWERUP_KINDS` 的固定索引访问池与 MultiMesh 组，离线校验器明确拒绝出现未定义的 `pu_kinds` 标识。

### 10. 城市建筑装饰增量平移

**原风险：**`_update_building_recycling()` 每帧对每栋楼调用完整 `_write_building_detail_transforms()`，即便该楼只是沿 Z 轴移动；其余装饰相对建筑的尺寸、横向位置和高度都没有变化。

**修复：**普通移动仅对已启用的屋顶、桅杆、信标、侧边栏杆和檐口实例读取变换并增加相同的 Z 位移；只有建筑循环回到远端、获得新尺寸与装饰旗标时，才重算完整装饰布局。该修改保持 MultiMesh 实例数量与绘制分组不变。按 88 栋楼、旗标生成概率估算，建筑未回收的常态帧，装饰 `set_instance_transform` 写入量从固定的 88×9=792 次下降到约 325 次/帧（约减少 59%）；这是按概率推算的写入数量，不是 FPS 提升百分比，仍须用 Godot Profiler 实测。

### 11. 共享激光材质脉冲去重

**原风险：**每个活动激光障碍都为同一份共享 `laserBeam` 材质重复写入同一帧颜色。

**修复：**仅当本帧遇到第一个活动激光障碍时更新共享颜色，后续障碍跳过相同写入。

### 12. 速度线状态边沿更新

**原风险：**速度线 `GPUParticles3D.emitting` 与共享材质透明度每次调用 Effects.update 都重新赋值，尽管它们只由“是否超频”和“是否超过速度阈值”两个状态驱动。

**修复：**缓存粒子开关状态与超频透明度模式，只有状态变化时才写属性；`reset_fx()` 同时复位缓存和常态透明度，避免重开局后缓存与实际材质不一致。

### 13. HUD 显示值缓存

**原风险：**分数、距离、芯片数和连击标签每个物理步都重新格式化文本并赋值，即使该整数或连击状态尚未变化。

**修复：**缓存各字段上次呈现值，只有显示内容/显隐状态变化时才更新 Label。距离/分数本身仍维持原来的整数显示规则，没有延迟玩家可见的数值变化。
