# v2.2.0-G 工程整理与新局稳定性复核

## 目标

减少“开始新局时状态残留”这一类跨系统问题，同时把源码维护流程变得更容易理解、复查和重复执行。此版本以 v2.1.0-G 为基线，采取兼容式重构，未重命名 `res://` 资源路径，也没有大规模搬动场景节点。

## 关键改动

- **新局两阶段提交：** `Main._start_run()` 只接受 `menu` / `gameover`，通过 `_starting_run` 防止重入；先关闭输入、清空队列、重置 Spawner、Player、特效、World、音频、HUD 和进度，再调用 `Game.start_run()` 发布 `running`。
- **状态所有权统一：** 暂停与继续改走 `Game.pause_run()` / `Game.resume_run()`，状态变化由 `state_changed` 通知协调层。Main 不再直接写 `game.state`。
- **完整复位契约：** `Player.reset()` 恢复瞬态物理与动画；`AudioEngine.reset_run_state()` 清理音乐 Tween、旧音效、Boss/超频锁、连击音量和上局章节索引；`HUD.reset_run_ui()` 清理 Toast、死亡覆盖层、道具与超频显示。
- **职责分组：** Main 的信号装配拆分为输入、菜单、玩家反馈、Game 事件、Spawner 事件和 Progress 六组方法。
- **可读性与目录整理：** 增加 `.editorconfig`，统一 GDScript 的空白习惯；历史审计资料归档到 `docs/audit/`，构建资料归入 `docs/build/`，新增项目地图、生命周期、开发规约、回归清单与发布清单。
- **单一离线检查入口：** `sh tools/run_offline_checks.sh` 运行 Python 工具语法和源码/资源契约检查；校验器还检查 Markdown 本地链接、GDScript 空白风格和新局生命周期顺序。

## 本轮执行的检查

- 9 个 GLB 模型、6 张 1024×1024 PBR 贴图通过资产检查。
- 46 处字面资源引用、30 个唯一导入 UID、工程版本 `2.2.0-G` 与 Android `versionCode=16` 一致。
- 9 首 OGG 与 12 个短音效 WAV 通过离线音频检查；所有音频文件均由 FFmpeg 完整解码。
- 重新运行短音效生成器后，12 个 WAV 的 SHA-256 与运行前一致。
- 固定随机种子参考向量、障碍时序、车道操控数值模型、存档/任务防护与新局源代码契约通过。
- 16 个 GDScript 文件的引号/括号词法扫描通过；16 个 Markdown 文件的本地链接与 16 个 GDScript 文件的空白风格检查通过。
- 最终交付 ZIP 从干净目录解压后，重新运行相同的离线检查。

## 未完成事项与诚实边界

当前执行环境没有 Godot 引擎、Android 导出工具和连接中的 Android 真机。因此，本报告**不声称** GDScript 语义编译、场景/Shader 导入、真实新局运行、音频听感、帧率/温度或 APK 安装测试已经通过。词法检查和源码契约只验证静态结构与预期调用顺序，必须继续按 [`../../REGRESSION_CHECKLIST.md`](../../REGRESSION_CHECKLIST.md) 在 Godot 4.7.x 和目标设备上完成验收。

## 建议的真实引擎优先测试

1. 从菜单启动；第一帧立即进行左右换道、跳跃和滑铲，确认没有旧输入。
2. 连续快速点击开始/重开，确认只出现一局并且活动障碍清空。
3. 在上一局处于 BOSS、超频、雨效、死亡姿态或音效重叠时结算，再立即开新局。
4. 连续重开至少 20 局，并反复暂停/继续、接受/拒绝复活，检查音乐、HUD、输入和道具状态。
5. 只有以上运行检查通过后，再在 Android 真机测冷启动、长时间运行和帧时间尖峰，最后导出并验证 APK。
