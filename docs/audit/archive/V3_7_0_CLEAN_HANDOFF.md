# v3.7.0-G — 赛博 PBR 纹理节奏与原生矢量 UI 精修审计

> 当前开发基线：v3.7.0-G（Android versionCode=33）。推荐验收引擎：Godot 4.7.2-stable。

## 本版目标

在 v3.6.0-G 原生 StandardMaterial3D detail overlay 基础上，继续检查材质平铺、纹理细节节奏与移动端 UI 的平台一致性。不是通过增加屏幕特效或无条件提高多边形数量来制造“升级感”，而是让赛博装甲、未来能量跑道和交互界面具备更清晰的层级。

## 实际修改

1. **装甲纹理布局精修。** `tools/generate_armor_textures.py` 使用 9 列 × 12 行的较大六角复合单元，并叠加 4×4 宏面板、内框、机械锁点和遥测线路。降低噪声的视觉权重，配合既有 RGBA detail mask，使细节呈现为接缝/刻线而不是铺满整块表面的蜂窝壁纸。同步将玩家/导入模型的 UV 比例分别调整到约 0.85/0.80，并降低法线强度，使小型部件更容易读出大面与边界。
2. **能量跑道纹理层级。** `tools/generate_road_textures.py` 收敛宽尺度云状噪声，让深蓝碳陶模块、机械分区、内嵌电路与边缘倒角成为主视觉。面板色调变化使用双轴周期函数，避免 V 方向平铺边缘颜色不连续；道路仍以赛博装甲跑道呈现，不使用现实沥青设计语言。
3. **严格 PBR 接缝合同。** 装甲/跑道的 Albedo 和 Normal 边缘统计阈值收紧为 1.55；当前六张 1024×1024 贴图全部通过。当前边缘比值：装甲 Albedo x/y=0.06/0.04，装甲 Normal=1.00/0.95；跑道 Albedo=0.70/0.54，跑道 Normal=0.99/0.98。打包材质的粗糙度 Alpha 与独立灰度源图逐像素一致。
4. **核心 UI 转为项目自带矢量图标。** 新增 9 个轻量 64×64 SVG：chip、pause、overclock、shop、mission、achievement、settings、play、home。HUD 与菜单以原生 TextureRect/Button/StyleBoxFlat 呈现，统一深色玻璃底、主题色边框与 hover/pressed 状态。去除高频 HUD/菜单中的 Unicode 装饰图示字符，降低系统字体回退导致图标大小、基线和字形不一致的风险。
5. **引擎测试入口可移植化。** 新增 `tools/run_godot_tests.sh`：支持显式 `GODOT_BIN`、系统 PATH，并严格检查 `RELEASE_MANIFEST.json` 指定的 Godot 4.7.2-stable；若引擎存在则运行 Editor 导入/解析、`test_headless`、`test_content`、`test_mechanics`、`test_runtime` 和主场景启动。引擎缺失会打印 SKIP，不把未运行写成通过。
6. **维护和版本同步。** 将项目、Android 导出预设、发布清单、当前维护文档与审计入口统一为 3.7.0-G / versionCode 33；旧 v3.6.0 审计移至归档。回归清单加入 SVG/XML、平铺连续性和正确引擎测试入口规则。

## 验证结果

- 9 个 GLB 模型：网格、UV、坏面、重复面和法线离线检查通过。
- 6 张 PBR 贴图：1024×1024、周期接缝、颜色范围、粗糙度 Alpha 对照通过。
- 9 个 SVG：XML 解析、viewBox、轻量矢量结构通过；HUD/菜单不再含主要平台字体图示字符。
- 75 个字面资源引用、104 个导入 UID、21 个 GDScript 词法结构扫描通过。
- 城市近景 96 栋/远景 80 栋的 12,000 帧回收数值模拟保持最大漂移约 6.253e-13 / 1.904e-12 米。
- 存档、回放、输入/车道、音频/声音优先级、生命周期、对象池、PBR 接线、性能策略和文档链接等离线合同通过。
- 两个 PBR 生成器连续各执行两次，六张输出贴图第二次的 SHA-256 与第一次逐字节一致；相对 v3.6.0-G 基线，六张 PBR 图均发生了实际内容变化。完整压缩包已通过 ZIP 完整性检查；新建干净目录解压后，重新运行 `sh tools/run_offline_checks.sh` 全部离线门禁通过，项目文档目录 `docs/build/`、9 个 SVG 与测试脚本均确认保留。

## 验收限制

当前执行环境没有 Godot 4.7.2-stable 可执行文件。故本报告不宣称 GDScript 语义编译、SVG/GPU Shader 实际导入渲染、主场景运行截图、Android APK 导出、平均/p95 帧时间、GPU 时间或温度已经实测。`run_godot_tests.sh` 是后续在指定引擎环境执行的入口；离线 XML/词法检查不能替代引擎验收。

## 建议的实机视觉复核顺序

1. 竖屏实际尺寸下检查暂停/超频热区、芯片图标与计数文本是否垂直居中，低分辨率缩放时是否仍清晰。
2. 在玩家、障碍、飞行器和地标上检查 detail overlay 是否保留原色，确认六角尺度与 UV 在每类模型上不是过密或过稀。
3. 以高速冲刺和普通跑动分别检查跑道电路、发光导轨、拱门和城市灯窗；不以编辑器贴图查看代替场景渲染验收。
4. 在目标 Android 设备记录 60/90/120 FPS 行为、p95 帧时间、热降频、连续游玩 15 分钟后的稳定性。
