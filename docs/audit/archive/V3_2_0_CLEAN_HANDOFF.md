# v3.2.0-G — 逐轮视觉与性能优化审计

> 当前开发基线：v3.2.0-G（Android versionCode=28）。推荐验收引擎：Godot 4.7.2-stable。

## 目标与边界

本次只针对模型/材质保真度、画面清晰度、视觉特效成本、帧时间与操作流畅度修改，不主动改玩法参数、碰撞规则、存档格式或操控映射。上一版本把 15 条检查/改动概括成“15 轮”，不足以证明完成 15 轮独立的深度迭代；本审计改按能从实际源码差异与验证结果佐证的轮次记录，不用数字充数。

## 实质优化轮次

### 第 1 轮 — 常态后处理减少无效屏幕采样

- `fx/post_fx.gdshader`：常态禁用色差时只取中心样本与锐化的四个相邻样本；不再额外读取红/蓝偏移样本。对应常态屏幕纹理采样由原来的 7 次降至 5 次。
- 颗粒与扫描线关闭时由分支跳过哈希/正弦逐像素计算；颗粒默认强度固定为 0。
- `fx/post_fx.gd` 删除无用的逐帧时间 uniform 更新；高速/超频才启用额外色差。保留原生分辨率、边缘锐化、MSAA 与各向异性过滤。
- 验证：静态 Shader 合同与括号平衡通过；没有可用 Godot Shader 编译器，因此实际编译/性能仍未测。

### 第 2 轮 — 窗格着色器复用随机值

- `world/building_windows.gdshader` 复用 `cell_random` / `cell_variation` 驱动窗灯、闪烁、局部色调和故障细节；重复 hash 调用由 8 处减为 4 处（不计单一 helper 定义）。
- 保留窗格边框、玻璃高光、招牌带和偶发 glitch 的视觉路径。
- 验证：离线回归检查 hash 调用预算、窗框/高光合同和 Shader 括号平衡通过；尚未在 Godot 导入后的 GPU 上测时。

### 第 3 轮 — 楼群滚动改为缓存本地坐标与根节点位移

- `world/world.gd`：96 栋近景楼及屋顶装饰通过共享根节点滚动；80 栋远景楼使用各自 MultiMesh 根节点滚动。缓存每个实例的局部 Z，避免正常帧反复调用引擎实例缓冲的 get/set。
- 只有楼体越过阈值需要循环回收、或周期性根节点重定位时，才更新相关实例/装饰变换。重定位会抵消父节点的偏移，因此保持世界坐标连续。
- 调用成本对比（源码路径）：原远景每个更新 tick 对 80 个实例各读/写一次变换；近景每个 tick 对 96 个楼体各读/写一次，并为满足装饰 flags 的屋顶/檐线等调用额外读/写。新方案在没有物件越界或周期重定位的正常 tick 中，这两组 MultiMesh 没有逐实例变换缓冲读/写；只有实例回收与重定位时才写入。
- 验证：工具将参考逐实例移动与根节点方案在变化速度及 45/60 Hz 步长下对比 12,000 帧；近景/远景最大世界坐标漂移分别约 `7.71e-13` / `1.90e-12`，远低于 `1e-6` 容差（纳米位显示为 `0.000000000`）。该脚本模型用于检验数学等价，并非 Godot 运行时测试。

### 第 4 轮 — 性能降档不靠降低清晰度

- `core/telemetry.gd` 的性能等级保持 4× MSAA 与 3D 原生渲染比例 1.0；不会因为进入中/低档而自动降到 2× 或关闭抗锯齿。
- 降档优先影响 Bloom 强度、阴影与雨/速度线粒子预算，从而优先保留模型轮廓和边缘清晰度。
- 验证：视觉合同会拒绝重新出现 `MSAA_2X` / `MSAA_DISABLED` 自适应降档路径。实际低端机帧率仍需真机测量。

### 第 5 轮 — 低档设备真正跳过 Bloom 合成

- 复核发现只调低 `glow_intensity` 并不等于减少 Bloom 多层合成器的处理步骤。
- 新增 `_apply_glow_profile()` 与显式 `_perf_profile`：中/高档按档位保持 Bloom，持续预算降至低档时禁用 glow 合成器，不用 `0.5` 一类亮度阈值猜档位。短时超频将临时恢复辉光提示，结束后返回当前性能档位策略。
- 验证：新回归合同检查低档 glow 开关和超频恢复路径。实际帧时间收益及低档关 Bloom 时的画面可读性必须在目标设备测量；不宣称当前已经测得 FPS 提升百分比。

### 第 6 轮 — 模型网格退化与法线体检

- 扩展 `tools/validate_visual_assets.py`：除顶点/三角索引/UV 外，进一步检查零面积或近退化三角面、同材质网格内部的重复三角面、非有限三角面积与非有限面法线。
- 复查当前 9 个 GLB：所有模型均为 0 退化/重复面、法线有限；这次没有发现需要冒险重生成模型的坏面，因此不凭空增加多边形数。
- 验证：该检查在离线验证器中通过；仍需用 Godot 导入后检查实际法线/材质表现及目标设备性能。

## 当前离线验证结果

完整离线验证包含模型/PBR 检查、资源路径和 UID、版本/Android 导出身份、模式库、玩法/存档/生命周期/回放合同、GDScript 词法扫描、文档链接、Python 工具语法以及根节点滚动数学等价模拟。打包前与干净解压后各执行一次 `sh tools/run_offline_checks.sh`。

- 9 个 GLB 模型：几何、UV、材质和最小三角数通过；追加退化/重复三角面与非有限法线检查，当前模型均为 0 退化/重复面。
- 6 张 PBR 纹理：尺寸/通道/有限像素/周期接缝检查通过，均为 1024×1024。
- 64 个字面 `res://` 资源引用、104 个导入 UID 的既有完整性约束通过（以离线工具最终日志为准）。
- 4 个离线验证器和 Python 工具语法检查通过。

## 未完成的验收

当前环境没有 Godot 4.7.2-stable 可执行文件，也没有 Android 真机；因此不能声称完成 GDScript 语义编译、GLSL/Shader 实际编译、真实渲染截图、平均/p95 帧时间或 GPU 时间测量、热稳定性测试、安装测试。城市滚动优化与 Bloom 调度的性能收益仍属于基于源代码执行路径的优化预期，而非真实设备测量结果。

## 发布边界

此交付包为完整源码 ZIP，不包含 APK、`.godot` 导入缓存、Python `__pycache__` 或发布签名私钥。Godot 导入与 Android 设备的最终验收仍必须在匹配工具链上完成。
