# v3.4.0-G — 全赛博视觉方向纠正与材质深化审计

> 当前开发基线：v3.4.0-G（Android versionCode=30）。推荐验收引擎：Godot 4.7.2-stable。

## 本轮目标

这轮纠正了前版的艺术方向问题：这款游戏是赛博跑酷，跑道的材料语言应来自未来科技设施。主视觉统一围绕未来科技设施、碳陶装甲模块、能量导轨、数据脉冲、复合机甲外壳和建筑电力通道。性能优化只能支持画面目标，不能取代画质升级。

## 实质修改与逐项复核

### 第 1 组 — 赛博跑道 PBR 资源与命名

- 将运行时道路材质资源由旧道路资源名统一改为 `cyber_deck_*`，同步更新三张 PNG、Godot `.import` sidecar、`world/world.gd`、生成器、验证器和当前文档中的引用。
- 重新生成 1024×1024 albedo、tangent-space normal 与 roughness 图。底色为深蓝黑碳陶复合装甲；加入模块接缝、加工倒角、二级装甲分割、服务接口环、蚀刻电路路径、数据刻线和粗糙/抛光区域差异。
- roughness 源图以线性灰度独立保存，像素原值同时复制到 albedo Alpha。离线验证逐像素校验一致性，未依赖第三次运行时纹理采样。
- 深化复查：降低随机颗粒在底色中的权重，提升装甲板本体的明度/细节对比；增加内嵌精密边框、四点数据锁和内部遥测槽，不靠堆噪声营造细节。
- 验证：三张地图均为 1024×1024，接缝比率在工具阈值以内，roughness Alpha 与源图逐像素一致；新增明度/高光分位数护栏确保 PBR 采样后的装甲板不会陷入过黑。

### 第 2 组 — 跑道材质着色器改造

- `world/road_grid.gdshader` 将表面结构定义为装甲模块，而非现实路面颗粒纹理。读取 PBR deck 颜色/粗糙度与法线两张纹理；保留移动端纹理采样预算。
- 添加随跑动平滑滚动的分段电力电路、主题色能量通道、双车道导轨、中心同步轨、周期脉冲标记与远景细节衰减。
- 通过材质粗糙度区分碳陶面板与抛光导能区，增强金属高光响应。没有降低渲染比例或关闭 4× MSAA。
- 验证：着色器结构括号、资源引用、两次 texture() 采样数量和必需的未来科技轨道特征合同通过。当前无 Godot 4.7.2 编译器，实际 Shader 编译/渲染观感仍需引擎验收。

### 第 3 组 — 机甲、障碍与交通模型的复合装甲微表面

- 重做 `tools/generate_armor_textures.py`：引入中性六角陶瓷复合细胞、微刻电路、加工分割、方向性微织纹和粗糙度差异，生成 1024×1024 albedo/normal/roughness。
- 维持接近中性的色值，避免覆盖模型原本的阵营色、章节调色和 emissive 灯带；只通过微表面与法线呈现制造工艺，不用贴图直接画出夸张发光色块。
- 深化复查：发现旧装甲 albedo 平均约 RGB 164/177/195，作为 `albedo_texture` 乘到导入材质会明显压暗原模型阵营色；改为近中性高亮底层（当前平均约 RGB 221/230/242），将深色集中在接缝/蚀刻槽，新增双切面内缘与单元内遥测刻线。
- 验证：三张装甲地图的分辨率、通道、可平铺接缝检查通过，粗糙度变化范围未坍缩；质量门禁核对 albedo 平均值及暗色槽线覆盖。

### 第 4 组 — 赛博城市立面电力通道

- `world/building_windows.gdshader` 加入分段电力脊线和水平冠部信号轨迹，复用每个 MultiMesh 实例已有的随机种子/窗格变化数据。
- 没有增加额外纹理读取、PointLight 节点或新增 hash 采样调用；保留现有窗框、玻璃高光、招牌与按可见细节门控的路径。
- 验证：原有 shader hash 预算、可见性门控、结构配对检查与新增 spine/crown 视觉合同均通过；实际远近景观感和 GPU 成本仍需运行时测量。

### 第 5 组 — 数据拱门的几何与材质层次

- 将过厚的 TorusMesh 主环重构为内半径 2.56、外半径 2.82 的薄型主环，并添加独立青色内导管、洋红外导管和一个 MultiMesh 内的八个信号刻度；圈层沿局部法线分离，避免共面闪烁。
- 4 个门框及其子部件关闭投影阴影，透明度随门框接近相机独立淡出；不为八个信号刻度创建单独节点，避免细节增加导致 draw-call 膨胀。
- 验证：回归合同锁定环半径、局部法线偏移、标记位置/切线方向和透明材质，防止退回过厚实心环。运行时视觉仍需引擎截图验收。

### 第 6 组 — 跑道与机甲 PBR 响应校准

- 将赛博甲板 albedo 平均 RGB 从约 `35/51/78` 提升至 `65/89/119`，让源颜色经 sRGB→linear 转换后不再过暗；主板碳陶材质金属度改为约 0.48，抛光导能区渐变至 0.82。
- 增加贴图像素统计门禁：跑道平均通道亮度与第 95 百分位蓝通道高光不得低于合同阈值；装甲细节贴图必须保持近中性高亮，并保留足够暗色槽线，以平衡颜色保护和微表面辨识。
- 验证：离线像素统计、贴图边缘/通道/粗糙度一致性与两次 Shader 采样合同一起执行。色彩在实际 Godot 灯光/色调映射下的主观观感仍需引擎验收。

### 第 7 组 — 导入路径、版本与艺术管线复核

- 更新道路资源名、`.import` 路径和所有活跃源码 preload；旧名只保留在历史审计档案内，不再作为当前艺术方向描述。
- 版本统一到 `3.4.0-G` / Android `versionCode=30`，同步 `project.godot`、`export_presets.cfg`、发布清单和当前文档入口。
- 更新验证器，检查赛博跑道设计标记、装甲纹理生成标记、楼宇脊线、roughness Alpha 等，移除已经失效的旧生成器源码硬编码。
- 验证：9 个 GLB 网格仍全部通过退化面/重复面/法线/UV 检查；6 张 PBR 纹理均通过尺寸、通道、边界与资源引用检查；装甲贴图的颜色保护阈值、跑道材质亮度/高光阈值一并纳入。

## 回归结果

- `tools/validate_visual_assets.py`：通过。
- `tools/validate_project_integrity.py`：版本升级、资源路径、UID 唯一性和文档入口检查已纳入全套门禁，打包前/打包后分别执行。
- 其余模式库、发布合同、音频解码、存档/回放/玩法源码合同和 GDScript 词法扫描：以最终全套离线门禁的输出为准。

## 未完成的真实验收

当前环境没有 Godot 4.7.2-stable 可执行文件。因此，本轮没有声称已完成 Godot 语义编译、Shader 实际编译、主场景截图、Android 真机 FPS/p95 帧时间、GPU/CPU 温度或长时间稳定性测试。生成的 PBR 图在独立图像查看器中检查过结构与细节，但这不替代引擎内材质/光照预览。发布前必须在目标 Godot 版本重新导入，并对 412×915 竖屏近/远景、章节变色、超频、正常与低端设备档位逐一验收。
