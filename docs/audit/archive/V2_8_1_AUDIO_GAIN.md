# v2.8.1-G 音频响度升级记录

## 目标

玩家反馈背景音乐和音效整体偏小。本轮针对当前 `v2.8.0-G` 音频管线，优先调整混音增益和不同短音效的响度补偿；不直接将所有 WAV 样本放大到接近满刻度，以免 UI 细声、低频提示和瞬态全部变得刺耳。

## 修改

- `systems/audio.gd`：压缩器阈值从 `-12 dB` 调整至 `-9 dB`，ratio 从 `3.0:1` 调整至 `2.5:1`，attack/release 改为 `250 µs / 160 ms`，makeup gain 设为 `+3 dB`。
- 在压缩器及轻混响后添加 `AudioEffectHardLimiter`，ceiling `-1 dBFS`，release `120 ms`，用于限制多轨混合的峰值。
- 给 12 个音效增加独立增益：`chip +1.0`、`jump +1.5`、`land +1.0`、`slide +1.5`、`die +1.0`、`powerup +1.5`、`overclock +1.0`、`ui +4.0`、`achv +3.5`、`ready +3.5`、`boss +0.5`、`revive +1.5 dB`。
- 记录每个活跃播放器当前播放的音效类型，设置音量变化时按对应的音效补偿刷新；滑块拉到 0 时，输出仍降到静音底限。
- 版本更新为 `2.8.1-G`，Android `versionCode=23`；离线校验器加入增益、补偿表、限幅器和版本一致性断言。

## 源文件初始响度检查

9 首 OGG 的 FFmpeg `volumedetect` 平均样本音量约为 `-13.9` 至 `-15.4 dBFS`，最大样本峰值约为 `-2.4` 至 `-4.1 dBFS`。12 个 16-bit PCM WAV 的峰值约为 `-7.0` 至 `-16.0 dBFS`；`ui`、`achv`、`ready` 原始电平最小。这些测量支持通过混音增益与 per-SFX trim 提升响度，而不需要破坏源音频或重做配乐。

## 静态增益估算（非引擎录音）

以 WAV 最大采样点和旧/新压缩器理想 transfer curve 估算，单音效峰值提升约 `+4.5` 至 `+7.0 dB`；特别短促的 UI 声音提升较多，原本偏响的 BOSS 提示提升较少。最终总线由 `-1 dBFS` hard limiter 保护。音乐平均音量估算提高约 `+3 dB`，峰值经压缩后保留余量。

## 验收

- 所有 Python 工具语法通过。
- 12 个 WAV 格式、时长、样本载荷及峰值范围通过。
- 9 首 OGG 与 12 个 WAV 由 FFmpeg 全轨解码。
- 版本字段、逐音效补偿、活跃 voice 音量同步和 hard limiter 契约通过。
- 最终 ZIP 完整性通过；干净解压目录重跑同一套离线校验通过。

## 尚待实测

当前环境无 Godot 4.7.x 可执行文件，也没有 Android 真机/扬声器音频回录。因而无法确认主观听感、真峰值、压缩泵动、不同机型响度、耳机/扬声器差异、启动延迟和长时间运行行为。玩家设备的系统媒体音量仍会影响实际输出。
